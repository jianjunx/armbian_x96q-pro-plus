# X96Q Pro+ H728 修正版 v2

镜像：`../armbian-build/output/images/Armbian_X96Q-Pro-Plus_H728_Bookworm_6.17-2_v2.img`，约 2.1 GiB。

SHA-256：`f3718e92a5ee1bfbc2f227bd3144f2c6f0234e6a761b5facd7ddd8b63c91ec29`。

## 本次修正

上一版实际 DTB 将 GMAC1 设为 disabled，没有配齐本盒子的以太网 PHY、电源与复位配置；USB3 和 CPU 调频配置也不完整。这能解释网络不可用，但没有串口日志，不能断定上一版内核是否已经启动。

本版保留 Armbian Debian Bookworm 用户空间，成套替换为论坛作者提供的 `linux-sunxi-6.17-2` 内核、模块与盒子 DTB。实际版本是 `6.17.0-rc1-2-MANJARO-ARM+`，属于实验性兼容版本，不是最新稳定版，也不是长期安全维护内核。

- 以太网：启用 GMAC1、地址 1 的 PHY，以及参考电源、复位配置。
- USB：使用配套 USB2、DWC3 USB3 和 SUN55I combo PHY 支持。
- CPU：设备树包含 8 个 Cortex-A55 核心、两组调频域、OPP 与温度配置。
- 驱动：将 Debian kmod 无法读取的 `.ko.gz` 解压成 `.ko`，重新生成依赖与 initramfs。
- 引导：设置标准 FAT32 LBA 启动分区，补充 extlinux 与 boot.scr 启动路径，开启串口早期日志。U-Boot 本身未更换，仍须验证是否适合你的硬件批次。
- 保留清华 Debian 软件源，锁定板级内核和启动相关包，避免普通升级替换这套组合。

以上通过离线检查；以太网连接/DHCP、USB 枚举、实际 CPU 在线数量与调频仍需要真机验收。校验记录位于镜像旁的 `.verification.txt`。

## 烧录与启动

1. 将整个 `.img` 写入 SD 卡，并启用烧录工具的写后校验。这会覆盖该 SD 卡；先备份，不要选择电脑系统盘。
2. 盒子断电，插卡，接网线到开启 DHCP 的路由器。首轮测试先不插移动硬盘等高功耗 USB 设备。
3. 上电等待约 2 分钟，查看路由器 DHCP 租约（主机名通常为 `x96q-pro-plus`），然后通过分配的 IP 进行 SSH 登录，完成原有 Armbian 首次登录流程。

**这一参考方案尚不支持 HDMI 输出，黑屏本身不代表启动失败。** 目前以网络和串口为主要验证方式。不操作盒子 eMMC，也不要执行安装到 eMMC 的命令。

进入系统后可检查：

```sh
uname -r
cat /sys/devices/system/cpu/online
lscpu
ip -br address
lsusb -t
sudo /usr/local/sbin/h728-diagnostics
```

预期内核为 `6.17.0-rc1-2-MANJARO-ARM+`；八核全部上线时 `online` 为 `0-7`。将低功耗 U 盘分别插入 USB 接口测试枚举。机械硬盘可能需要独立供电，不能仅凭设备树启用就认定盒子的 USB 供电足够。

## 如果仍然没有 IP

系统进入用户空间后约 60 秒会在 SD 卡 FAT 启动分区生成 `h728-diagnostics.txt`，之后每 3 分钟更新一次。等几分钟再断电，将卡插回电脑，把该文件发给我。日志包含 CPU、网卡、USB 和内核消息；对外公开前请检查 IP/MAC 等信息。

如果没有该文件，并不能单凭此判断具体故障阶段，需要 UART 启动日志进一步定位。使用 **3.3 V TTL** 串口、115200/8N1，确认板上引脚后仅接 GND、TX、RX，不接适配器 VCC，更不能用 RS-232 电平或 5 V TTL。不要盲目更改 DRAM/电压参数。

## 本地复现入口

源文件在本目录；构建在现有特权容器 `h728-image-build` 中进行。其 `/armbian` 映射本机 `armbian-build`。现有缓存保留了参考包展开目录 `/armbian/cache/h728-audit/reference` 及从 Image 提取的 `reference.config`。

`rebuild.sh` 使用原始 6.18.48 镜像作为用户空间底包，会核验原始镜像与参考包哈希。参考包须复制到容器 `/tmp/h728-reference.pkg.tar.zst`，本目录须复制到 `/armbian/cache/h728-v2-input`。脚本拒绝覆盖已存在的 v2 镜像；需要重新构建时先另存已有产物。它不是一条从空目录重新编译全部源码的命令。

```sh
docker cp reference-packages/linux-sunxi-6.17-2-aarch64.pkg.tar.zst h728-image-build:/tmp/h728-reference.pkg.tar.zst
docker cp revision-v2/. h728-image-build:/armbian/cache/h728-v2-input/
docker exec h728-image-build bash /armbian/cache/h728-v2-input/rebuild.sh
docker exec h728-image-build bash /armbian/cache/h728-v2-input/verify.sh
```

源码和参考来源：[Manjaro H728 初始支持帖](https://forum.manjaro.org/t/allwinner-h728-a523-a527-t527-initial-support-thread/173654)。普通 Armbian `compile.sh` 仍使用原始主线构建配置，不会自动生成这里的 v2 配套内核版本。
